# World-first delivery boundary (0.10.0)

The product authority is not a Three.js scene. sem-lang owns definitions and
memory; Hatter owns role, Work, grant and publication lifecycles; the source
owners hold their own data; delivery exposes bounded, exact-reference
projections. The DOM renderer owns only camera, placement, visible instances,
selection and an ephemeral user-context marker. Destroying a mesh never deletes
an owner record. An action is usable only if the current delivery projection
declares its target and input contract; the renderer cannot invent it from a
type, icon, title or proximity.

```text
sem-lang / HAT / Hatter owner state
  -> canonical producer + publication -> exact delivery document
  -> bounded client projection -> World / Map / Timeline / detail
  -> input intent -> exact target + declared capability -> owner command
```

Existing presentation is classified as follows:

| Existing concern | World-first destination |
| --- | --- |
| Person roster and selected Role | World presence; person context bubble |
| Saved observations and unresolved meanings | Exact focused-person information shelves in the panel; book/detail and review bubble |
| Short-term observations and explicitly promoted long-term context | One read-only memory timeline for the exact Role; the two memory classes remain visibly distinct |
| Human sensory perspective | Six stable presentation positions around the person; records enter a position only through an adopted semantic binding, otherwise they remain explicitly unclassified |
| Declared operations and owner input forms | Context interaction; 2D form overlay |
| Work and local inference observation | Person/agent status and minimal HUD |
| Current scene and explicit relations | World; same-reference Map view |
| Owner diagnostics, catalogs and model administration | Deliberate 2D system detail |
| Full-page navigation for an already selected subject | Retire after exact context parity |
| Temporary observed-change list | HUD notification; not event history |

The first slice has one World canvas, a minimap using the same projected IDs,
third-person presence when exploring, keyboard/touch movement, target selection,
context interaction, and compact person-specific inference status. A shelf is a
panel index over the current published Scene, never a 3D semantic object. It is
shown only when the Scene focus is the selected Role; its records open through
their exact RenderPlan IDs. Characters alone occupy the garden. Visible NPCs
have individually phased, low-frequency presentation motion; this is not
semantic travel or evidence of inference. Offscreen characters and reduced-motion
clients do not animate. The overview
camera remains available for discovery and accessibility. A marker is currently
session-local presentation context bound to an exact owner reference, not a
durable semantic fact. No automatic reasoning, authority or action is created
by camera movement or marker placement.

Product gaps are explicit: the current garden roster publishes Role/person
subjects only (maximum 32). The existing RenderPlan supplies exact, bounded
person information without a new Console endpoint. No Organization/System
semantic roster, spatial query over 10,000 owner entities, durable user-context
marker owner, or token-level model progress is currently published. Those need
their respective owners' source/reference and authorization contracts before
the UI can claim larger city/campus scenarios, durable cross-device markers or
live model generation. In particular a 3D animation may never stand in for
model progress. The renderer must not fill these gaps with sample-only objects.

“World” is the owner-local Digital Twin presentation. It is not a user-visible
workspace and does not own another data store. The memory timeline joins only
equal Role and semantic revisions from sem-lang's retained observations and
accepted claims. It uses an explicit evaluation/observation instant when one
exists and leaves the entry untimed otherwise. Sensory positions are likewise
presentation affordances: labels, source text, predicates, or proximity are not
used to guess sight, hearing, touch, smell, taste, or body sensation.

Test gate: scenario tests prove exact-reference selection through World and Map,
camera/presence ownership, no fabricated actions, bounded rendering, and
disposal/re-projection. Browser tests cover desktop/mobile, no screenshot,
no external request, and no inference triggered by the render loop. A complete
10,000-entity performance acceptance requires a bounded spatial-query owner
contract; the existing 32-person delivery boundary cannot be described as that
acceptance.

| Requested scenario | Current proof / boundary |
| --- | --- |
| Person focus → context → owner interaction | Installed sample browser; context opens without a command, explicit Open conversation selects the exact Role |
| Agent event → inference → authority → command | Hatter Work/Grant and declared feedback exist; this World slice observes them but does not introduce an NPC decision loop or assert model token progress |
| Far entity marker → near detailed model | Pure bounded projection test; no product spatial-query owner yet |
| Map selection → same World focus | Renderer browser and installed sample browser |
| Offscreen Agent works without animation | Renderer is event-driven and does not call inference on render; actual offscreen Agent task publication requires a producer scenario |
| 10,000 semantic / 1,000 logical / 200 detailed | Pure 10,000 → 200 projection test only; product delivery remains bounded to 32 Role objects |
| Dispose → exact re-projection | WebGL loss/restore and 20 disposal cycles in browser test |

The current browser reference reports one draw call, one geometry, zero textures
for the small scene; visible NPC ambient motion is capped at 5 frames/second
and reduced-motion clients have no ambient frames. These are headless
Chromium measurements, not mobile GPU performance claims. Marker state is
discarded with the World view; product persistence needs an owner contract.
