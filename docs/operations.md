# Current Console operation

Start Hatter with an explicit HATTER_HOME and its verified Console handoff.
The shared Rust product root owns the canonical owner processes and one Node
helper. Stop the product root normally; Console must not own duplicate databases.

Open http://localhost:4213/. The world shows currently adopted people, not a
fixed tutorial roster. Choose **Open people**, choose **Talk to** for one person,
then **Open conversation**. The conversation starts with that person's published
questions and confirmations when present; otherwise it shows the latest retained
information. Information, processing status and declared operations remain
separate choices in the same conversation. The compact Back control returns to
those choices. The edge menu exposes view controls and System; the connection
indicator opens original failures and notifications.

A fresh `hatter state initialize` creates product metadata only. It does not
adopt a sem-lang definition package, create a Role, install HATs or invent a
person's information. Without adopted definitions and a bound Role, the world
is empty and presents the current setup state. The isolated
`hatter-sample.*` environment used by tests is different: it explicitly adopts
a fictional definition and three sample Roles (Personal, Learning, Project),
then retains fictional observations. Those records are never default personal
data. First-use definition-package selection and Role binding remain product
work; the UI must not suggest that adding a HAT alone creates the first person.

Building source does not switch the active immutable generation. Use the exact
current preview command recorded in the root migration report for source validation.
